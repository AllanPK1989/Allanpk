# PM Planning, Scheduling & Tracking System

A complete preventive-maintenance system built on Microsoft 365: a Power BI
dashboard, a QR-code-driven Power Apps front end, SharePoint templates, and a full
dummy dataset so everything works end to end before any real data exists.

**PM scheduling is driven by production standard hours.** Hours accrue per cell from
a monthly Excel upload; at 4000 accumulated hours the whole cell is scheduled, with
a 12-month calendar backstop for cells that never get there.

## Build it

```bash
pip install openpyxl "qrcode[pil]" pandas

python3 scripts/generate_dummy_data.py          # 16 CSVs
python3 scripts/build_sharepoint_templates.py   # 18 Excel templates
python3 scripts/generate_qr_codes.py            # QR codes + print sheets
python3 scripts/build_measure_docs.py           # measure documentation
python3 scripts/build_pbip.py                   # the Power BI project
python3 scripts/validate_pbip.py                # 692 consistency checks

# build_pbip.py also rezips the project to PM_Dashboard_pbip.zip on every run,
# so the downloadable archive can never drift from powerbi/.
```

Then unzip or copy `powerbi/` to **`C:\PM_Dashboard`** and open
`PM_Dashboard.pbip` in Power BI Desktop. The CSVs ship inside the project at
`data/`, and the `LocalDataFolder` parameter already points there — refresh works
with no edits. Full detail in [`docs/11-opening-the-pbip.md`](docs/11-opening-the-pbip.md).

If that project will not open on your Desktop version, save a blank `.pbip` from
Desktop and run:

```bash
python3 scripts/build_pbip.py --inject "C:/path/to/Blank.pbip"
```

## The dummy plant

8 cells · 33 machines · 10 technicians · 42 spare part lines · 100 checklist tasks
· 24 months of history to Aug 2026 plus a 12-month forecast · 261 work orders ·
1,763 checklist results · 196 breakdowns · 216 abnormalities · 1,659 QR scans.

Loadings differ enough that some cells trip roughly every three months and at least
one rides the calendar backstop, so every branch of the scheduling rule is
exercised by the data rather than only by the code.

## Going live

The Power BI model reads dummy CSVs or real SharePoint data depending on one
parameter:

| Parameter | Development | Production |
|-----------|-------------|------------|
| `SourceMode` | `Local` | `SharePoint` |
| `LocalDataFolder` | `C:\PM_Dashboard\data` | ignored |
| `SharePointSiteUrl` | ignored | `https://<tenant>.sharepoint.com/sites/PMSystem` |

Everything else — tables, relationships, all 94 measures, all 10 pages — is
unchanged between the two.

## The parts that matter most

**The upload is the single point of failure.** If Production stops uploading
standard hours, counters freeze and nothing is ever scheduled — while the dashboard
still looks green. That is why `Missing Std Hours Rows` is a KPI on its own page
and why one of the six flows exists purely to chase the file.

**Closing a work order requires being at the machine.** There is no "mark as done"
button. A job leaves the technician's list when the machine QR is scanned and the
checklist submitted. `QR Verification %` and `Desk Closed WOs` make the exceptions
visible.

**Compliance alone can be gamed; the model knows it.** `PM Compliance %` sits next
to `Checklist Fail Rate %` and `Breakdowns Within 15d of PM` precisely because
100% compliance with a 0% fail rate and rising post-PM failures means the
checklists are being clicked through, not worked through.
